# 音楽科 週案帳（Firebase版・PINログイン）

PC（自宅・職場）・スマートフォン・タブレットから同じURLで開けて、
**PINコードだけ**でログインすると、データが自動的にクラウド
（Firebase Firestore）に保存されるバージョンです。
Googleアカウントは使いません。JSONファイルの書き出し・読み込みも不要です。

---

## 認証方式について（比較・採用理由）

このアプリは「あなた1人だけが、複数端末から使う」という前提です。
検討した認証方式と、それぞれの特徴は次のとおりです。

| 方式 | メリット | デメリット | 採用 |
|---|---|---|---|
| メール/パスワード認証（ふつうのログイン画面） | Firebase標準機能。複数端末対応。実装が簡単 | 画面に「メールアドレス」欄が出るため、職場PCなどでは少し仰々しい | – |
| 匿名認証 | ログイン画面が不要で一番シンプル | **端末ごとに別のID（uid）が発行される**ため、複数端末でデータを共有する用途にはそもそも使えない | ✕（今回の目的に合わない） |
| カスタムトークン方式（PINをCloud Functionsで検証） | 4桁PINなど好きな形式にできる | Cloud Functionsのデプロイ、Blazeプラン（従量課金）契約が必要になり、構成が複雑になる | – |
| **PINコード（内部ではメール/パスワード認証を流用）** | 画面には数字・記号だけの入力欄で済み、Googleアカウント等を一切意識しない。Firebase標準機能のみで実現でき、追加インフラ不要 | Firebaseの仕様上、パスワード（＝PIN）は6文字以上必須。忘れたときは登録メールアドレス宛にリセットメールを送る形になる | **◎ 採用** |

**採用した方式**：画面には「PINコード」の入力欄だけを表示します。
内部的には、あらかじめ決めた1つのメールアドレス（`config.js` の
`APP_AUTH_EMAIL`、画面には出ません）と、あなたが入力したPINを
「メールアドレス／パスワード」として扱う、Firebase標準の
メール/パスワード認証を使っています。

- 初めて使うとき：入力したPINでアカウントが自動的に作られます。
- 2回目以降：同じPINを入力するとログインできます。
- PINを忘れたとき：「PINを忘れた場合はこちら」から、`APP_AUTH_EMAIL`
  宛にFirebase標準のパスワード再設定メールが届きます。

このため、追加のサーバーやCloud Functionsを用意しなくても、
「見た目はPINだけ」「実体は安全なFirebase認証」という構成が実現できています。

## ファイル構成

```
music-planner-firebase/
├── index.html            起動ページ（Firebase SDK読み込み・全体の入れ物）
├── style.css              デザイン（見た目）
├── app.js                 アプリ本体（画面の描画・操作・データ加工ロジック）
├── firebase-service.js    Firebase認証・Firestore読み書きのラッパー（★役割はこの1ファイルに集約）
├── config.js              Firebase接続情報 + PINログイン用メールアドレス（要編集）
├── config.example.js      config.js のひな形
├── firestore.rules        Firestoreのセキュリティルール（自分のデータだけ読み書き可）
├── .gitignore
└── README.md              このファイル
```

Firebase関連の処理（初期化・ログイン・データ読み書き）はすべて
`firebase-service.js` に集約しています。画面の見た目や操作ロジックは
`app.js` に、デザインは `style.css` に分かれているので、
「Firebaseまわりだけ直したい」「見た目だけ直したい」といった場合に
迷わず編集できます。

## 1. Firebaseプロジェクトを作る

1. https://console.firebase.google.com/ を開き、Googleアカウントでログインします（＝Firebaseの管理画面に入るためのログインです。アプリ自体のログインとは別物です）。
2. 「プロジェクトを追加」→ プロジェクト名を入力（例：`music-weekly-planner`）→ 画面の指示に沿って作成します（Googleアナリティクスは無効のままで問題ありません）。

## 2. Webアプリとして登録し、config を取得する

1. 作成したプロジェクトのトップ画面で、`</>`（ウェブ）アイコンをクリックします。
2. アプリのニックネームを入力（例：`music-planner-web`）し、「アプリを登録」をクリックします（Firebase Hostingのチェックは不要です）。
3. 表示された `firebaseConfig` の値をコピーします。
4. `config.example.js` を `config.js` という名前でコピーし、次のように書き換えます。

```js
window.FIREBASE_CONFIG = {
  apiKey: "実際の値",
  authDomain: "実際の値",
  projectId: "実際の値",
  storageBucket: "実際の値",
  messagingSenderId: "実際の値",
  appId: "実際の値",
};

// あなたが実際に受信できるメールアドレスにしてください（PINを忘れたときの再設定に使います）
window.APP_AUTH_EMAIL = "your-email@example.com";
```

> `FIREBASE_CONFIG` の値は「公開されても問題ない」設計です（Firebaseの仕様）。実際のアクセス制限は後述のFirestoreセキュリティルールで行うため、`config.js` はそのままGitHubにコミットして構いません。

## 3. Firebase Authentication（メール/パスワード）を有効にする

1. Firebaseコンソールの左メニュー「構築」→「Authentication」→「始める」。
2. 「Sign-in method」タブ →「メール／パスワード」を選び、**有効にする**→保存。
   （Googleは有効化不要です。使いません。）

## 4. Firestore Database を作る

1. 左メニュー「構築」→「Firestore Database」→「データベースの作成」。
2. ロケーションを選択（`asia-northeast1`＝東京 などお好みで）。
3. 「本番環境モード」を選んで作成します。
4. 作成後、「ルール」タブを開き、`firestore.rules` の内容をそのまま貼り付けて「公開」をクリックします。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

ログインした本人（＝PIN認証で発行されたuid）だけが、自分の
`users/{自分のuid}` ドキュメントを読み書きできます。他人はもちろん、
未ログイン状態でも一切アクセスできません。

## 5. GitHubにアップロードする

1. GitHubで新しいリポジトリを作成します。
2. このフォルダの中身（`index.html`, `style.css`, `app.js`, `firebase-service.js`, `config.js`, `firestore.rules`, `.gitignore` など）をすべてアップロードします。

## 6. Vercelにデプロイする

1. https://vercel.com/ にアクセスし、GitHubアカウントでログインします。
2. 「Add New...」→「Project」→ 先ほどのリポジトリを選択して「Import」。
3. Framework Presetは自動的に **Other**（静的サイト）になります。ビルド設定は不要で、そのまま「Deploy」をクリックします。
4. 数十秒でデプロイが完了し、`https://(プロジェクト名).vercel.app` のようなURLが発行されます。

Googleログインを使わないため、承認済みドメインの追加設定は不要です。

## 7. 動作確認

1. デプロイされたURLを開く。
2. PIN入力欄に好きなPIN（6文字以上）を入力し「ログイン」→ 初回はこれでアカウントが作成されます。
3. 「設定」タブでクラス・時間割を登録し、「週案」タブで入力してみる。
4. 別のブラウザ・別の端末で同じURLを開き、**同じPIN**でログインすると、同じ内容が表示されることを確認する。

## データの持たせ方・保存タイミング

- Firestoreの `users/{uid}` という1つのドキュメントに、クラス設定・時間割・週ごとの授業内容・めあて等をまとめて保存しています。
- 画面を操作すると、0.8秒の入力停止後に自動的にFirestoreへ保存されます。右上の「保存中…」「同期済み：HH:MM」が状態表示です。保存ボタンはありません。
- 一般的な1年間の利用データはおおよそ数百KB程度に収まる想定です（Firestoreの1ドキュメントの上限は1MB）。

## セキュリティについて

- `config.js` の値は「秘密鍵」ではなく公開前提の識別子です。実際の保護はFirestoreのルールと認証が担っています。
- Firebase Authenticationには、パスワード（PIN）の連続失敗に対する一時ロックなどの保護が標準搭載されています。
- より安全にしたい場合は、PINを6桁の数字ではなく、8文字以上の英数字混在にすることをおすすめします（画面の入力欄は文字数の制限をしていないため、そのまま長くできます）。

## 今後、機能を追加しやすくするための構成

- **役割ごとにファイルを分離済み**：Firebase関連（`firebase-service.js`）／見た目（`style.css`）／画面ロジック（`app.js`）が分かれているため、たとえば「認証方法だけ変える」「見た目だけ変える」といった変更がしやすい構成です。
- **データ構造がシンプル**：`config`（クラス・時間割）／`weeks`（週ごとの授業内容）／`objectives`（めあて）の3つのオブジェクトだけで完結しています。新しい項目を足したいときは、この3つのどれかにフィールドを追加するだけで対応できます。
- **複数端末のリアルタイム同期**：現在は「開き直すと最新化される」方式です。開いたまま自動的に反映したい場合は、Firestoreの `onSnapshot`（リアルタイム購読）に差し替えることで対応できます（`firebase-service.js` の `loadUserData` 周りの変更のみで済みます）。
- **週ごとにドキュメントを分割**：長期間・多クラスで運用してデータが大きくなってきた場合、`users/{uid}/weeks/{週の開始日}` のようにサブコレクションへ分割する設計に変更できます（読み込み速度の改善にもつながります）。
- **PIN以外の認証への切り替え**：`firebase-service.js` の `signInWithPin` を差し替えるだけで、将来的にメール/パスワードのふつうのログイン画面や、他の認証方式に変更することも可能です。

## よくある質問

**Q. PINを忘れてしまった**
ログイン画面の「PINを忘れた場合はこちら」を押すと、`config.js` の `APP_AUTH_EMAIL` 宛にFirebase標準のパスワード再設定メールが届きます。そのメールの手順でPINを再設定してください。

**Q. ローカルで動作確認したい**
`index.html` のあるフォルダで簡易サーバーを立てて開いてください（`file://` で直接開くと一部機能が制限される場合があります）。
```
npx serve .
```

**Q. 複数端末でログインしたら、片方の変更がもう片方に自動で反映されますか？**
現在の実装では、ページを再読み込みすると最新の内容を取得します。開いたままリアルタイムに反映したい場合は上記「今後、機能を追加しやすくするための構成」を参照してください。
